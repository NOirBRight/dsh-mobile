# DSH 0.1.1-rc.2 plugin compatibility

Date: 2026-08-22

## Scope and source boundary

This note compares the repository's pinned baseline, [`dsh-v0.1.1-rc.1` at `528c682e…`](https://github.com/deepseek-ai/deepseek-harness/tree/528c682e061696f5a160f363f236ecbf53cbd006), with the official [`dsh-v0.1.1-rc.2` tag at `b150a551…`](https://github.com/deepseek-ai/deepseek-harness/tree/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e). The evidence is the official [tag-to-tag diff](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.1.1-rc.1...dsh-v0.1.1-rc.2), [rc.2 release commit](https://github.com/deepseek-ai/deepseek-harness/commit/aa6c361a972c8369148dea7380bb5c21c24e07ec), and tagged first-party source, manifests, and docs only. The local baseline is independently recorded in [`patches/dsh-runtime-session-hydration.json`](../patches/dsh-runtime-session-hydration.json).

## Compatibility verdict

**Ordinary bundle, settings-card, and slot-only plugins should need no manifest migration.** rc.2 does not change the `dsh.bundle.patch` / `dsh.profile.bundles` model, the `dsh.client` boot declaration or wire shape, settings slot names, UI-layout source, or CLI/Web startup source. It does bump the whole DSH package family, so rebuild and test client bundles against rc.2 rather than assuming an rc.1 graph revision remains valid.

**Retest or adapt plugins that touch sessions/permissions, images, LLM adapters, or an HTTP proxy.** Those are the plugin-facing changes in the compare range.

| Area | rc.1 → rc.2 | Third-party impact |
|---|---|---|
| Session client/wire API | `SessionsPort.create`, `SessionRuntime.create`, and the Host `sessions.create` payload drop `reuseWorkspaceBlank`. The Workspace runtime now returns an eligible existing blank directly rather than re-adopting it through the Host ([rc.2 client port](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/runtime/src/client/contract/sessions-port.ts), [Workspace reuse](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/runtime/src/client/workspaces/service.ts), [Host API](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/host/apiproxy/src/api/sessions.ts)). | Remove the flag from typed callers and raw RPC payloads. A wrapper that used create/adopt as a side-effect boundary must not expect that call on blank reuse. |
| Permission defaults | A default now applies only when a session is created; `PermissionPresetService.refreshDefaultForReuse` and durable selection `origin` are removed ([service source](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/interaction/permission-presets/src/index.ts), [config catalog](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/config-catalog.md#deepseek-aidsh-permission-presets)). | Do not refresh or reinterpret an existing blank when the setting changes. Event readers must accept rc.1 payloads with optional `origin` and rc.2 payloads without it. |
| Permission identifiers | Runtime source still uses Settings namespace `permission`, event `permission/preset`, and command `/permission` ([namespace/event](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/interaction/permission-presets/src/index.ts#L72-L85), [command](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/interaction/permission-presets/src/index.ts#L270-L292)). rc.2's package README instead says `permissionPresets` / `permissionPresets/preset` / `/permissionPresets` ([README](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/interaction/permission-presets/README.md#L5-L17)). | Treat the README spellings as a documentation inconsistency; **do not migrate runtime keys** to them. |
| Permission/conversation UI | Built-in localized permission-label keys are removed. Kebab-case names become title case and `danger-full-access` is always shown as `Full access`; the confirmation body remains localized ([component](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/ui-conversation/src/client/skeleton/PermissionSelect.tsx), [presentation helper](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/ui-permission-presets/src/client/presentation.ts)). | Update screenshot/text assertions and do not depend on translated built-in labels. Custom non-kebab labels still pass through. |
| Attachment provider API | `ImageAttachmentRef` gains optional `originalDimensions`; `ImageVariantId`, `ImageRequestPolicy`, and `RequestImageAttachment` are added. `AttachmentStore.readImageRequest()` has a default implementation that rejects with `ATTACHMENT_PROJECTION_UNSUPPORTED` ([public API](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/attachment/attachment/src/index.ts), [types](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/attachment/attachment/src/types.ts)). | Existing subclasses still construct, but an image-capable custom store must implement deterministic request-image projection or explicitly remain unsupported. Preserve the optional metadata when copying refs. |
| LLM adapter API and behavior | `LlmAdapter.prepareCall()` and `PreparedAdapterCall` bind model facts to dispatch; `PreparedLlmCall` gains `inputModalities`. Text-only routes now replace durable images with deterministic text rather than rejecting model selection ([LLM API](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/llm/llm/src/index.ts), [projection helpers](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/llm/llm/src/content.ts)). | The inherited method preserves basic adapters. Dynamic adapters should override it so capability metadata and endpoint/stream dispatch come from one generation. Recheck middleware that expected an image-related model-selection error. |
| Cordis image config | `attachment-local` adds normalization/concurrency options and raises the default aggregate submitted-image budget to 200 MiB. DeepSeek removes `maxRequestImageBytes` in favor of Files/inline/count/offload settings; pi-ai retains its aggregate option and adds per-image pixel/byte settings ([attachment config](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/config-catalog.md#deepseek-aidsh-attachment-local), [DeepSeek config](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/config-catalog.md#deepseek-aidsh-llm-deepseek), [pi-ai config](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/config-catalog.md#deepseek-aidsh-llm-pi-ai)). | Update overlays that configure official image/LLM rows. A patch replaces a row's whole `config` rather than deep-merging it, so restate every required key ([official bundle guide](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/user/develop/basic/publish.md#the-loading-order)). |
| HTTP bridge | Default `maxRequestBodyBytes` increases from 160 MiB to 300 MiB to carry the 200 MiB aggregate image budget after base64 expansion ([connection source](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/connection/src/http-bridge.ts)). | Reverse proxies, tunnels, and request buffers may impose a lower effective cap. Confirm the intended cap and failure behavior; do not assume rc.1's 160 MiB default. |

## Confirmed stable surfaces

- **Client boot manifest:** `window.__DSH_BOOT__` remains `{ rev, entries }`; each entry remains   `{ id, url, rev, inject?, immediately?, external? }` ([rc.2 wire types/parser](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/packages/client/modules/src/client/manifest.ts#L42-L108)).   The graph and row `rev` values are content consistency anchors, not compatibility versions; never hard-code them.
- **Bundle/profile contract:** package `dsh.bundle.patch`, ordered `dsh.profile.bundles`, user `cordis.patch.yml`,   and `dsh plugin --profile …` retain the documented behavior ([official packaging guide](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/user/develop/basic/publish.md#the-profile-manifest)).
- **Settings slots:** the Host/browser namespace join and keyed `settings.plugin.item` registration are unchanged   ([rc.2 settings-card contract](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/cookbook/adding-a-settings-card.md)).
- **Layout and startup:** no source change appears in `packages/client/ui-layout/src`, CLI source, Web Vite entry,   frontend-static, or webserver; only package versions move. Continue starting the injected app with   `npx @deepseek-ai/dsh@0.1.1-rc.2 web`, not bare Vite, because the shell requires the Host-injected manifest   ([official run guide](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/README.md#run), [Vite guard](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/apps/web/vite.config.ts)).
- **Node:** the root engine remains `^22.19.0 || >=24.0.0` in both tags   ([rc.1 manifest](https://github.com/deepseek-ai/deepseek-harness/blob/528c682e061696f5a160f363f236ecbf53cbd006/package.json#L7-L9), [rc.2 manifest](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/package.json#L7-L9));   official contributor docs list CI coverage for Node 22.19, 24, and 26   ([development guide](https://github.com/deepseek-ai/deepseek-harness/blob/b150a551b8d465e31e418e1b2eaf5e79bbb7d28e/docs/development.md#prerequisites)).

## Two-baseline plugin validation checklist

Run the same plugin artifact against two **fresh, isolated** homes/profiles—one pinned to `@deepseek-ai/dsh@0.1.1-rc.1`, one to `@deepseek-ai/dsh@0.1.1-rc.2`—using Node 22.19+ or a supported 24+ release.

### On both rc.1 and rc.2

- [ ] Install through `dsh plugin --profile <test-profile> add <plugin-spec>`; confirm the package appears in       `dsh.profile.bundles` and `--dump-config` shows the plugin layer in the intended order.
- [ ] Start through `dsh web`; confirm Host activation has no missing injection, schema, duplicate-row, or peer-package error.
- [ ] For a client half, confirm its package id appears once in `window.__DSH_BOOT__.entries`, its bundle URL loads,       and its Cordis fiber becomes active. Do not compare literal graph or bundle revisions across versions.
- [ ] Exercise every contributed slot, command, RPC/event subscription, and settings card; save, reload, restart, and       verify the setting namespace joins the same Host and browser halves.
- [ ] Create, select, archive, resume, and cold-reload sessions. Confirm raw RPC clients tolerate only the fields       advertised by that version's schema.
- [ ] If the plugin handles images or models, test text-only and image-capable routes, nested tool-result images,       custom attachment storage, cancellation, and over-limit errors.
- [ ] If the plugin proxies DSH, test ordinary JSON, WebSocket reconnect, and a representative large image request;       verify the proxy's explicit limit rather than allocating a 300 MiB test in routine CI.
- [ ] Run the plugin's typecheck/tests once against each version's public packages, then smoke-test the packed artifact;       avoid shipping a second incompatible copy of a host-owned DSH service package.

### Version-specific assertions

- [ ] **rc.1:** if testing permission-default changes with an eligible reused Workspace blank, expect the confirmed       reuse path to refresh a still-default-origin blank.
- [ ] **rc.2:** remove `reuseWorkspaceBlank`; expect an existing blank to remain pinned and only a genuinely new       session to read the latest default.
- [ ] **rc.2:** update obsolete DeepSeek image config, implement or deliberately reject `readImageRequest` in custom       attachment stores, and update permission-label snapshots.
- [ ] **rc.2:** verify runtime identifiers remain `permission`, `permission/preset`, and `/permission` despite the       rc.2 permission-presets README wording.

## dsh-mobile consequence

The optional session-hydration enhancement is deliberately allowlisted to rc.1 commit `528c682e…` and runtime revision `5a9e129c42ae`. Keep that enhancement disabled on rc.2 until its patch/revision and two-tier tests are explicitly updated; the repository policy already falls back to the unmodified compatible Core plugin for an unknown runtime ([local compatibility metadata](../patches/dsh-runtime-session-hydration.json)).
